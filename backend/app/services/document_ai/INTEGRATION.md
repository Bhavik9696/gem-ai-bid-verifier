# Document Intelligence - Integration Guide for Core API (Member 3)

This document provides the integration contract for the Document Intelligence module. This module strictly extracts and syntactically validates data from raw documents, passing structured `ExtractedFact` objects to the Core API for downstream compliance evaluation.

## 1. How Core API calls Document Intelligence

The Core API should invoke the exposed `process_document` synchronous function. It acts as a resilient pipeline chaining: File Validation → OCR Fallback → Classification → Field Extraction → Syntax Validation.

## 2. Input Structure

```python
from app.services.document_ai import process_document

def process_document(document_id: str, file_name: str, file_content: bytes) -> DocumentResult:
```

- `document_id`: A unique string UUID generated by the Core API to trace the document across services.
- `file_name`: Original filename (e.g., `company_pan.pdf`). Used for MIME validation and classification heuristics.
- `file_content`: Raw byte array of the file payload.

## 3. Output Structure (`DocumentResult`)

The function returns a `DocumentResult` Pydantic model with the following top-level properties:

- `document_id`: The ID passed in.
- `document_type`: Enum (e.g., `PAN`, `GST`, `UDYAM`, `UNKNOWN`).
- `processing_status`: Enum (`SUCCESS`, `PARTIAL_SUCCESS`, `FAILED`).
- `extracted_fields`: A dictionary mapping field names to `ExtractedFact` objects.
- `validated_fields`: A dictionary mapping field names to `ValidationResult` objects.
- `errors`: A list of strings containing critical failures (e.g., "File too large").
- `warnings`: A list of strings containing non-critical OCR issues (e.g., "Page 2 unreadable").

### The `ExtractedFact` Contract

Each extracted fact strictly aligns with the shared project architecture:

```json
{
  "field": "PAN",
  "value": "ABCDE1234F",
  "confidence": 0.99,
  "documentId": "doc-123",
  "page": 1,
  "evidence": "Matched valid PAN format: ABCDE1234F"
}
```
*(Note: If a field does not exist in the document, `value` will be `null` and `confidence` will be `0.0`)*

## 4. Error Handling

The Document Intelligence module is designed **never to crash the Core API orchestrator**.
- Internally, all exceptions are caught gracefully.
- If a catastrophic error occurs (e.g., corrupted PDF, file size >10MB, completely unreadable scan), the function returns a `DocumentResult` with `processing_status = "FAILED"`.
- The exact failure reasons will be appended to the `errors` list.
- **Action**: The Core API should simply check `if result.processing_status == "FAILED"` before passing payloads to the compliance pipeline.

## 5. Low-Confidence Behavior

The module **never guesses** missing fields. 
- If multiple conflicting identifiers are found (e.g., two different GSTINs on one page), the module extracts the first one but strategically drops the extraction `confidence` (e.g., `0.80`).
- The internal semantic validator will catch this low confidence and mark the field's validation status as `NEEDS_REVIEW`.
- The overall document `processing_status` will shift to `PARTIAL_SUCCESS`.
- **Action**: The downstream Compliance Engine (Member 5) can use these flags to suspend automation and flag the bid for human review.

## 6. Python Usage Example

```python
import uuid
from fastapi import UploadFile
from app.services.document_ai import process_document

async def handle_document_upload(file: UploadFile):
    # 1. Read bytes from upload
    file_bytes = await file.read()
    doc_id = str(uuid.uuid4())
    
    # 2. Invoke Document Intelligence Pipeline
    result = process_document(
        document_id=doc_id,
        file_name=file.filename,
        file_content=file_bytes
    )
    
    # 3. Handle Errors natively
    if result.processing_status == "FAILED":
        return {"error": "Document processing failed", "details": result.errors}
        
    # 4. Extract facts array for the compliance engine
    facts_for_compliance = list(result.extracted_fields.values())
    
    # 5. Hand off to Member 5's pipeline
    # compliance_result = run_compliance_engine(facts_for_compliance)
    
    return result.dict()
```
