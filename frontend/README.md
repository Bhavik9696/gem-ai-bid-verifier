# ComplianceOS Frontend

Next.js officer dashboard connected to the ComplianceOS Core API. Tender, bid, assessment, verification, decision, and audit data are loaded from the backend; the frontend does not substitute demo records when the API is unavailable.

## Run locally

Start the backend and its dependencies from the repository root:

```bash
docker compose up --build
```

Then start the frontend:

```bash
cd frontend
npm ci
npm run dev
```

Open `http://localhost:3000`. The browser calls `http://localhost:8000` by default. Set `NEXT_PUBLIC_API_BASE_URL` before starting Next.js to use another Core API URL. The Compose frontend service sets this value to `http://localhost:8000` for browser-side requests.

## Backend contract

The frontend uses these routes implemented in `backend/app/api/routes.py`:

| API route | Frontend use |
| --- | --- |
| `GET /health` | Header backend status |
| `GET /api/tenders` | Dashboard, tender list, bid selection, audit, and reports |
| `GET /api/tenders/{tenderId}` | Tender eligibility and rulebook details |
| `GET /api/tenders/{tenderId}/bids` | Tender bids and summary assessments |
| `POST /api/bids/{bidId}/run-verification` | Run verification from the bid profile |
| `GET /api/bids/{bidId}/assessment` | Rules, findings, verification results, extracted facts, and audit events |
| `POST /api/bids/{bidId}/decision` | Persist officer decision and reason |
| `GET /api/bids/{bidId}/audit-events` | Tender audit timeline |

The frontend route segment named `[bidderId]` contains a **bid ID**, since the assessment, verification, decision, and audit endpoints all require `bidId`. For example, seeded bid `GEM-BID-2026-001` is opened at `/bidders/GEM-BID-2026-001`; its associated bidder ID is a separate value.

An assessment is absent until verification is run. The backend returns `404` for that state; the UI displays it as pending and offers the verification action. Officer decisions accept `CONFIRM`, `REQUEST_CLARIFICATION`, or `OVERRIDE`; the latter two require a reason.

## Backend limitations surfaced in the UI

The current Core API does not expose tender/bid import, document upload/download, bid detail, or document metadata endpoints. The ingestion route therefore lists available backend tenders and explains that importing is not supported. The documents view displays extracted facts and backend-provided document references from an assessment; it cannot show original files or claim OCR has run before an assessment exists.

Reports are exported in the browser from API bid summaries and available assessment responses. They are not generated by a backend report service. Login is also still a frontend prototype and is not backed by an authentication API.

Connector result `mode` values come from the backend. Demo results are identified as demo data and are not represented as live government verification.
